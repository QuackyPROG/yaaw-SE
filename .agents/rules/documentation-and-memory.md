# Documentation and Memory

Durable knowledge belongs in the smallest canonical repository artifact that owns it. Threads are disposable working memory.

Use:

- ADRs for durable architecture decisions and consequences;
- specs for intended behavior/constraints;
- initiative maps for progressive L3/L4 destination/decisions/fog;
- tickets for executable bounded work and dependencies;
- scoped docs for stable subsystem facts/procedures;
- code/tests for executable truth.

Do not create giant running memory files, copy whole transcripts into tickets, or duplicate one decision across many authoritative documents. Prefer links/pointers plus a concise gist.
