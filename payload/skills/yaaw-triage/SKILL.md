# yaaw-triage

Move issues on the project's GitHub repo through a small state machine, using the `gh` CLI. An external PR is an issue with code attached: it uses the same states, with the differences marked below.

Start every comment posted during triage with:

```
> *This was generated by AI during triage.*
```

## Labels

- **Category** (exactly one): `bug` or `enhancement`.
- **State** (exactly one): `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` or `wontfix`.

When the repo uses other label names, map them once with the user and use the mapping from then on. When state labels conflict on an issue, flag it and ask before doing anything else.

An unlabelled issue goes to `needs-triage` first. From there it moves to `needs-info`, `ready-for-agent`, `ready-for-human` or `wontfix`, and `needs-info` returns to `needs-triage` once the reporter replies. The user can override any of this.

## What needs attention

List 3 groups, oldest first, with a count and one line per item: unlabelled, `needs-triage`, and `needs-info` with reporter activity since the last triage notes. For PRs, include only external authors' PRs and tag each line `[PR]` or `[issue]`. Let the user pick.

## Triage one issue or PR

1. **Gather context.** Read the body, comments, labels and dates (and the diff, for a PR), plus any earlier triage notes, so nothing is asked twice. Then run 2 checks: whether the behaviour is **already implemented** (search by domain concept, and say where you looked), and whether it matches a **prior rejection** in `.out-of-scope/`.
2. **Recommend** a category and state with the reasoning and a short summary of the relevant code. Wait for the user.
3. **Verify the claim.** Reproduce a bug from the reporter's steps. For a PR, check it out and run the relevant tests. Report: confirmed (with the code path), failed, or not enough detail.
4. **Probe if needed.** Run `yaaw-probe` and `yaaw-domain` to shape the request, one round at a time.
5. **Apply the outcome:**
   - `ready-for-agent`: post an agent brief ([AGENT-BRIEF.md](AGENT-BRIEF.md)).
   - `ready-for-human`: the same brief, plus why it cannot be delegated.
   - `needs-info`: post triage notes (template below).
   - `wontfix`: when already implemented, point to where it lives. When a bug is rejected, explain politely. When an enhancement is rejected, record it in `.out-of-scope/` ([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)) and link it. Then close.

Confirm every label change, comment and close with the user before it is posted, as it is visible to others.

## Needs-info template

```markdown
## Triage Notes

**What we've established so far:**

- point 1

**What we still need from you (@reporter):**

- a specific, answerable question
```
