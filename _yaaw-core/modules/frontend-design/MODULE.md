# Frontend design module

Use for UI components, layouts, styling, interaction, responsive behavior, or accessibility.

Planner: discover the existing design system/components/tokens and define only load-bearing UI requirements: information hierarchy, states, responsive behavior, accessibility, interaction invariants, and reuse constraints.

Implement: reuse established components/tokens first; preserve typography/spacing/color conventions; implement loading/empty/error/disabled/focus states; maintain keyboard and screen-size accessibility; avoid arbitrary visual systems when the project already has one.

Review: inspect actual rendered/structural behavior for consistency, responsiveness, accessibility, state coverage, and needless one-off styling.

Project-specific design decisions outrank generic aesthetic preferences when they are accepted/canonical.
