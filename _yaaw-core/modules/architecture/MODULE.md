# Architecture module

Use when work changes subsystem boundaries, shared interfaces, durable contracts, or foundational structure.

Planner: identify current constraints, alternatives, dependency effects, migration/compatibility cost, and record durable decisions when future work depends on them. Prefer existing repository patterns unless evidence justifies change.

Review: verify implementation follows accepted architecture and did not introduce hidden coupling or incompatible contract changes.

Do not expose low-level architecture trivia as stakeholder questions unless the choice has a real product/operational consequence requiring human authority.
