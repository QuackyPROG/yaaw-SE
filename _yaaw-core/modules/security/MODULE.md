# Security module

Use for authentication, authorization, secrets, privacy, payments, sensitive data, trust boundaries, abuse paths, destructive actions, or security-significant dependencies.

Planner: model assets/actors/trust boundaries, least privilege, abuse/failure cases, data exposure, recovery, revocation, compatibility, and verification requirements. Security/trust work floors to the configured high-assurance route.

Implement: preserve boundaries, avoid secret leakage, enforce authorization at trusted boundaries, and use existing secure primitives rather than ad-hoc crypto/security mechanisms.

Review: actively test/inspect authorization bypass, cross-tenant access, replay/race behavior, secret exposure, unsafe defaults, destructive recovery, and evidence adequacy.

Stakeholder questions must describe understandable consequences, not security implementation jargon.
