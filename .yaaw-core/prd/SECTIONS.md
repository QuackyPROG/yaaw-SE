# Canonical PRD interview sections

These are **areas to understand**, not a rigid ten-round questionnaire. One batch can cover more than one section. Ask only about material unknowns. If the user's answer reveals a new feature, flow, risk, exception, or audience, revisit the affected sections.

1. **Product vision (`vision`)** — What are we making? What experience should it deliver?
2. **Intended users (`audience`)** — Who is it for? Who is explicitly not the audience?
3. **User problems (`problems`)** — What is currently difficult, slow, risky or impossible?
4. **Desired outcomes (`outcomes`)** — What improvement matters to users? How will they notice it?
5. **Features (`features`)** — What can each user do or accomplish? Which are essential?
6. **User journeys (`journeys`)** — Entry, first use, primary use, repeated use, exit; roles and permission-visible behavior.
7. **Edge cases (`edge-cases`)** — Empty or missing information, failed actions, duplicates, cancellations, mistakes, unavailable services, access loss, and recovery as perceived by users.
8. **Scope and exclusions (`scope`)** — What is in the first release, postponed, and deliberately excluded?
9. **Product rules (`rules`)** — User-visible restrictions, privacy expectations, approvals, notifications, accessibility or compliance needs, only if relevant.
10. **Acceptance (`acceptance`)** — Examples a non-engineer can use to decide whether the product behaves correctly.

## Interview quality

- Prefer 3–6 questions per batch; allow 1–10 when justified. Never manufacture questions to hit a quota.
- Start with purpose/users; then expand into core actions, paths, boundaries and edge cases. Do not ask technical architecture questions.
- Each question is one crisp sentence, followed by choices **A**, **B**, **C**, a recommendation with one sentence of reason, and `Other: explain in your own words`.
- Recommendations are contextual, not defaults. Never infer selection from silence; a user can combine options or reject all options.
- Treat newly discovered behavior as a new question frontier, not permission to invent a decision.
- Once a section is clear, stop re-questioning it unless new evidence conflicts.
