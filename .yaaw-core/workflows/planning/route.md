# Planner route

Read `product.md`, `engineering.md` if present, state, and relevant repository reality before selecting a planning workflow.

Priority:
1. repository discovery/understanding missing -> `discover` + `write-understanding`;
2. current decision frontier unresolved -> `question-round`;
3. answers pending recording -> `record-decisions`;
4. readiness not established -> `readiness-review`;
5. ready frontier lacks spec -> `create-spec`;
6. accepted spec lacks executable tickets -> `create-tickets`;
7. later evidence invalidated a contract -> `replan`.
