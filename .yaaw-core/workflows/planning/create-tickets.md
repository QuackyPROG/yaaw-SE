# Create tickets

Precondition: accepted spec exists.

Split the spec into dependency-aware `TASK-NNN` files. Each ticket must be one coherent change that a fresh Implementer can execute without the planning chat.

Every ticket includes source spec, product constraints, referenced `ENG-*` decisions, relevant areas, required behavior, allowed scope, non-goals, acceptance criteria, required tests, dependencies, expertise hints, and status.

Set `READY` only when dependencies and planning admission are satisfied; otherwise use `DRAFT`.
