# Expertise: frontend-design

## Description
Specialist UI interaction, responsive behavior, accessibility, state-feedback, and component-boundary guidance. It grants no workflow authority.

## Required context
Relevant UI files, existing design-system/project rules, user-facing acceptance criteria, and current component patterns.

## Rules
Planner defines interaction states, responsive behavior, component boundaries, accessibility constraints, and testable acceptance. Implementer preserves local design-system conventions and complete loading/error/empty/disabled/focus states. Reviewer verifies the actual behavior across states and viewport/keyboard conditions.

## Anti-patterns
Inventing visual requirements, redesigning unrelated surfaces, treating desktop-only behavior as complete, or ignoring semantics/focus/labels.

## Verification expectations
State coverage, responsive behavior, semantic structure, keyboard/focus behavior, labels/errors, and regressions.
